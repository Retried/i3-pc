## Diagnoza i zakres poprawki

- `linux-sdl-gcc`, `linux-sdl` i `macos-sdl` zatrzymały się na
  bezwarunkowym `<intrin.h>` w `vk_rasterizer.cpp`. GCC nie znajduje nagłówka;
  Clang na Linux/macOS trafia na nieistniejący `include_next <intrin.h>`.
- W tym runie `windows-sdl` oraz wszystkie trzy joby C++ Tests zakończyły się
  sukcesem. Nie dowodzi to poprawności gry ani działania na konkretnym GPU NVIDIA.
  Konfiguracja `ENABLE_TESTS=ON` nie tworzy targetu emulatora (`if(NOT
  ENABLE_TESTS)` w `CMakeLists.txt`), dlatego zielone testy nie weryfikowały
  kompilacji rasterizera. Build testów i build emulatora sprawdza się osobno.
- Poprawka wybiera `<intrin.h>` przy `_MSC_VER` (MSVC i clang-cl) oraz
  `<x86intrin.h>` dla GCC/Clang x86-64. Wywołania `__rdtsc()` pozostają
  bez zmian. Nie zastąpiono ich zegarem o innej semantyce ani wariantem z fences.
- Sprawdzono również sąsiednie zależności: `vk_command_stream.cpp` i
  `vk_semaphore.cpp` korzystają z `<immintrin.h>` / `_mm_pause()` dostępnych
  na docelowym x86-64. Windowsowy sampler ma osłonę `_WIN32` i pustą
  implementację na innych systemach; API Windows w statystykach rasterizera,
  page managerze i RenderDoc jest warunkowane platformą. Nie zmieniano tych ścieżek.
  Oba joby macOS w workflow wybierają x86-64; natywny ARM64 pozostaje poza
  zakresem tej poprawki.
- Ciała funkcji rasterizera i cache pipeline'ów są identyczne z wersją HEAD
  po przepuszczeniu obu wersji przez clang-format-19. Zmiana funkcjonalna
  ogranicza się do wyboru nagłówka; pozostałe zmiany C++ to formatowanie,
  uporządkowanie includes i usunięcie powtórnego `<chrono>`.
- Nie zmieniano shaderów, profilu Vulkan, synchronizacji, konfiguracji
  workflow, testów ani istniejących ustawień kontroli CI.

## Weryfikacja i ograniczenia

- MSVC x64 i clang-cl x64: kompilacja próby z identycznym wyborem nagłówka
  oraz wywołaniem `__rdtsc()` zakończona powodzeniem.
  Dezasemblacja wszystkich czterech prób potwierdziła instrukcję `rdtsc`.
- Clang 19.1.5: próby freestanding skompilowane do plików obiektowych dla
  `x86_64-unknown-linux-gnu` oraz `x86_64-apple-darwin`. Weryfikują
  nagłówek i intrinsic, nie pełny emulator ani bibliotekę systemową.
- Brak lokalnego GCC, środowiska Linux/WSL i macOS. Pełne buildy GCC/Clang
  Linux i macOS trzeba ponowić w CI po opublikowaniu zmian; nie są tutaj
  oznaczone jako zaliczone.
- Build istniejących testów Windows x64, clang-cl 19.1.5, RelWithDebInfo:
  PASS. `ctest --output-on-failure -E GcnTest` (ten sam zakres co workflow):
  507 testów, 0 błędów, 3 pominięte przez istniejące warunki testów, 34,43 s.
  Nie uruchomiono grupy `GcnTest`, którą wskazany workflow również wyklucza.
  Pominięte przez same testy: `HostOverride.ActiveExactHostMatchFromJsonFile`,
  `NetP2PTcpKernelInterop.Unsupported`, `NetLib.UnixDatagramSockets`.
- Osobny pełny build emulatora Windows x64, clang-cl 19.1.5, RelWithDebInfo:
  PASS, łącznie z linkowaniem `shadps4.exe`. Końcowe potwierdzenie buildu
  zakończyło się kodem 0. Build używał poprawnie wybranego 64-bitowego
  toolchainu; nie wymagał zmian konfiguracji CI ani źródeł poza opisaną poprawką.
- Nie przeprowadzono uruchomienia gry ani prób na sprzęcie NVIDIA.
- Nierozwiązany, świadomie pozostawiony zakres: 44 starsze zgłoszenia
  clang-format wymienione powyżej. Brak nowych potwierdzonych błędów kompilacji
  nie oznacza, że kompilatory, których tu nie uruchomiono, nie ujawnią kolejnych.
