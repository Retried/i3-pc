# Standalone input repair (2026-10-17)

## Findings and changes

The installed standalone configuration selected unified bindings from
`dist/user/input_config/default.ini`. That file exactly matched the generic
runtime defaults, while the intended WASD/mouse/motion profile was shipped in
`dist/input_config/CUSA00004.ini` and was never imported. The active generic
profile did not provide the documented keyboard controls or spray gestures.
The PC controls editor also edited a per-game file even when unified input was
active. It now reads and writes the same profile as the input parser.

Standalone launches import a bundled per-game profile when creating that
profile. An untouched generic unified setup with no existing per-game profile
is migrated once; custom default and existing per-game profiles are preserved.
The selected binding path is logged. The local installation has been repaired:
the per-game profile is active and saves were not modified. Its prior settings
and repair record are in `runtime/Build/input-fix-20261017/`.

The start screen's Options row now opens PC display, controls and language
settings immediately, without loading a save or waiting for the game's native
pause menu. Escape/B returns to the start screen. Native game options remain
available through the game's pause screen.

PC menu navigation uses SDL key/button events before overlay and guest input
capture. Keyboard arrows/WASD, Enter/Space, Escape/Backspace, controller D-pad,
left stick and A/B share this route. Confirm/back ignore keyboard repeats.
Game display windows marked NoNavInputs no longer capture keyboard/gamepad
navigation, and controller button/axis releases can clear held state through
overlays. Explicit OSK/IME interception remains intact.

The generic binding/chord implementation and emulated motion/touch machinery
are reused. No game code, renderer or guest pad ABI changes are involved.

## Controls

| Action | Keyboard/mouse | Xbox |
| --- | --- | --- |
| Move / camera | WASD / mouse (F7 capture) | Left / right stick |
| Jump / confirm | Space or Enter | A |
| Pause | Escape | Start/Menu |
| Hold spray can sideways | Hold G | Hold LB+RB |
| Shake can | Hold H while holding G | View+X while holding LB+RB |
| Spray / aim can | Hold G, left mouse and mouse aim | Hold LB+RB, RT and right stick |
| Touch swipe | I/K/J/L | View+D-pad |
| Both touch contacts | Hold U | Hold L3+R3 (both stick buttons) |

Xbox has no motion sensor, so these chords supply the missing gestures. View
is the button to the left of the Xbox logo. Single buttons retain their normal
bindings; longer matching chords take priority. The active file is
`dist/user/input_config/CUSA00004.ini`; F8 reloads bindings.

The two-contact chord uses L3+R3 to avoid sharing View with the normal touchpad
click output. A View+A trial exposed the regular click release overwriting the
two-contact click when the chord formed, so that proposed binding was replaced.
